# Puckling: Pebble, an Orca session companion

Pebble is a compact pixel-art orca on the Waveshare **ESP32-S3-Touch-AMOLED-1.75C**. It shows which existing Orca session needs you and opens that exact tab and pane. It covers unarchived projects, multiple sessions per workspace, Claude Code, Codex, terminals, and local native chats.

The [approved design](docs/pebble-design.md) and its images are preserved as references. Production sprites are original indexed pixel artwork in [firmware/assets](firmware/assets), generated by `python3 tools/build_sprites.py` without external dependencies.

## Controls

- Swipe horizontally between **Home**, **Attention**, and **Sessions**. Three dots indicate the screen.
- Swipe vertically or tap the arrow targets to step through cards. Browsing wraps.
- Tap **Open in Orca** to focus the displayed existing session. Dragging cancels a tap.
- After opening a Home request, **Next request** intentionally selects another unseen request. Opening does not answer questions or resolve failures.
- With nothing pending, Home shows **All clear** and **Browse sessions**. An empty list and a lost connection have separate states.

Requests and failures precede new completed results. Seen unresolved requests remain visible. Sessions includes active sessions and results from the last 24 hours. Historical completions do not become new alerts on startup. See [ordering and acknowledgement](docs/orca.md).

The display preserves the selected identity through snapshots. A removed target becomes unavailable until you deliberately select another. Unknown or stale status disables opening. Opening reports **Opening**, **Opened**, **Retry open**, or an unavailable/unsupported target. There is no tab creation or remote answering.

## Setup and simulator

On macOS, install Homebrew, Xcode command line tools, Bun, and Python 3. `make setup` installs raylib and PlatformIO. Orca must be installed and running for live use.

```sh
make setup
make sim           # shared firmware UI, initially Status unknown
make sim-live      # daemon -> raw PTY -> simulator
make test          # deterministic daemon, parser, gesture, bridge and focus checks
make validate-sim  # native windows with synthetic Orca; screenshots and logs
make firmware      # compile ESP32 firmware, no upload
```

Simulator input uses the mouse: press, drag, release. The same UI, sprite data, JSON parser, gesture recognizer, and action encoder run on the puck. `display.cpp` and `sensors.cpp` remain board-specific.

```sh
python3 sim/live.py --screenshot /tmp/pebble.png --capture-after 3
```

`ORCA_CLI_COMMAND` selects the Orca executable. The daemon polls every two seconds. It never sends prompts or terminal contents to the device or logs. Synthetic validation replaces Orca entirely and cannot switch real sessions.

## USB puck

Firmware and daemon must both speak protocol v2. The board is the **1.75C**, whose pins differ from the plain 1.75. See [hardware](docs/hardware.md).

```sh
make firmware
make flash                         # only when you choose to upload
make puck-live                     # one /dev/cu.usbmodem* device
make puck-live PORT=/dev/cu.usbmodem2101
make monitor PORT=/dev/cu.usbmodem2101
```

Stop the live bridge before flashing or monitoring. Ctrl-C stops its daemon and closes the port. After unplugging, reconnect and restart `make puck-live`. The bridge preserves partial writes and bounds queued data to 64 KiB per direction. After eight seconds without fresh source metadata, navigation is disabled.

## Implementation and validation

The three screens, original Pebble sprites, individual session model, bounded browsing, exact-target focus receipts, USB transport, staleness handling, and touch gesture tracking are implemented for simulator and firmware. The daemon retains the full active/recent list while snapshots carry at most 32 cards, including pinned selections. All cards remain reachable by stepping.

Deterministic checks exercise actual shared firmware rendering and input. Screenshots and logs are under `sim/build/validation/`. [Validation report](docs/validation.md) records results, retained evidence, and limitations. Firmware was compiled, not uploaded or tested on physical hardware during this implementation. The read-only live smoke check verified metadata access, not live navigation.

Notifications are visual and silent. A brief dot batches new attention events, and requests remain visible. Audio cues, mute, lift-to-wake, face-down control, and twist navigation remain hardware work. The firmware dims after 60 seconds without touch and moves Pebble subtly; physical AMOLED brightness and touch release timing need device validation.

## Roadmap

- Verify touch, USB latency, frame rate, dimming, and palette on the 1.75C.
- Add one short soft audio cue per batched attention event, with mute and hardware validation.
- Evaluate lift-to-wake and face-down mute after core hardware checks.
- Consider durable acknowledgement across daemon restarts and an Orca status subscription if available.

Pebble has expressions and personality, with no pet-care progression or transcript-derived mechanics.
